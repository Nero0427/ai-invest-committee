# 投资委员会 · 多智能体投研系统

一个可以在本地跑起来的「投资委员会」。把真实投研团队的分工搬到代码里：
四位分析师各出报告，多头和空头研究员结构化辩论，风控官把关，交易执行官给方案 —— **最后一票由人投**。

参照 [TradingAgents](https://github.com/TauricResearch/TradingAgents) 的角色设计思路，
但完全独立实现：**只用 Python 标准库，零第三方依赖，不需要 pip install。**

## 能做什么

左侧三个页面，打开默认落在大盘云图：

| 页面 | 内容 |
|---|---|
| **大盘云图** | 热力图：颜色＝涨跌幅，按板块分组，30 秒自动刷新，**A股 / 美股可切换**。悬停显示该标的近 60 日走势，点击直接进投委会。下方附当日龙虎榜 |
| **龙虎榜** | 上榜个股明细，点列头可对任意字段升降序排序；点任意一行展开**买入 / 卖出席位**（营业部、买入额、卖出额、净额） |
| **投委会** | 八位 AI 委员对单个标的的完整研判流程（下面详述）。输入框支持**指数 / 个股 / 板块**三类检索，带下拉补全 |

「投委会」这一页做的事：输入一个**个股代码**或**板块名称**，系统会：

1. 拉取实时行情、日K线、成分股、资金流向、财经快讯
2. 召集 8 位 AI 委员依次发言（含一轮多空辩论）
3. 生成一份带**具体价位**的结论：评级、共识度、核心逻辑、主要风险、支撑位/压力位/目标区间/建议仓位/止损位
4. 等你拍板：通过 / 修改 / 驳回

**支持的市场**

| 类型 | 举例 | 覆盖 |
|---|---|---|
| A股个股 | `600519`、`sz000858`、`600519.SH` | 沪深主板、创业板、科创板 |
| 美股个股 | `LITE`、`NVDA`、`AAPL` | 纳斯达克 / 纽交所 / 美交所，直接输 ticker 即可 |
| A股板块 | `885362`、`881101`、`白酒` | 480 个（行业 90 + 概念 390，同花顺指数体系） |
| 美股板块 | `XLK`、`SMH`、`科技` | 35 个（SPDR 等行业 ETF，分 11 个大类） |
| 指数 | `上证指数`、`沪深300`、`创业板指` | 4 个常用宽基指数 |
| 商品 | `沪金`、`伦敦金`、`沪银` | 7 个品种（贵金属为主），仅行情 |

**关键价位是真算的，不是模型编的。** 支撑位取「MA20 / 近20日低点 / 布林下轨 / 60日低点」中低于现价的最高者，
压力位对称取上方最低者，止损 = 支撑 × 0.98。程序保证 `支撑 < 现价 < 压力` 恒成立。

## 快速开始

**环境要求：Python 3.9 或以上。就这一条。**

不需要 Docker，不需要 git，不需要 npm，不需要任何 API key 就能先跑起来。

### Windows

双击 `start.bat`

### macOS / Linux

```bash
python3 server.py
```

浏览器会自动打开 `http://127.0.0.1:8848`。

### 第一次打开

打开就是**大盘云图**：全市场热力图按行业分组，红涨绿跌，30 秒自动刷新。点任意方块直接进投委会分析。

其余页面从左侧切换。投委会这一页的用法是：

1. 搜索框输入 `LITE` 或 `白酒`（会弹出下拉建议），点「召开投委会」
2. 「浏览板块」可以按分类浏览全部板块
3. 想接真实大模型的话，点左下角「设置」填入 API key

不填 key 也能跑 —— 系统会自动退回到内置的规则引擎，用真实行情和技术指标生成判断。
深度不如大模型，但数据是真的。

## 在线部署

仓库里已经放好部署配置（`render.yaml`），**不需要改任何代码**，也不用写 Dockerfile。

> **为什么不放 GitHub Pages**：Pages 只能托管静态文件，跑不了 Python。而这个项目的核心
> —— 8 位 AI 委员的 SSE 推流、全市场 5913 只的分页抓取、技术指标计算 —— 全在 Python 侧。
> 就算把逻辑搬进浏览器也不行：同花顺、东财、新浪这三个数据源**都不发 CORS 头**，
> 浏览器跨域请求会被直接拦掉。所以需要一个能跑 Python 的托管。

### Render（推荐，免费）

1. 打开 [render.com](https://render.com)，用 GitHub 账号注册或登录
2. **New → Blueprint**，选中 `ai-invest-committee` 仓库
3. Render 会自动读到 `render.yaml`，直接点 **Apply**
4. 等 1–2 分钟构建完成，得到 `https://ai-invest-committee.onrender.com`

以后每次 `git push`，Render 自动重新部署，不用手动操作。

**免费层的两个已知点**：

| 现象 | 原因 |
|---|---|
| 闲置一阵后首次打开要等约 50 秒 | 免费实例休眠，唤醒需要时间；唤醒后就正常了 |
| 重启后第一次请求慢几秒 | 文件系统是临时的，`cache/` 会重建一次 |

区域默认选的新加坡（`render.yaml` 里的 `region`），离国内最近。

### 接真实大模型

在 Render 的 **Environment** 标签页加一个变量即可，不用改代码：

| Key | Value |
|---|---|
| `DEEPSEEK_API_KEY` | 你的 key |

不加也能跑 —— 系统会退回到内置规则引擎，用真实行情和技术指标生成判断，只是深度不如模型。
**别把 key 提交进仓库**（`.gitignore` 已经挡了 `config.local.json` 和 `.env`）。

## 工作原理

### 三段式流水线

```
数据采集
   ↓
【分析团队】基本面 · 技术面 · 新闻 · 情绪   ← 四位并行出报告
   ↓
【结构化辩论】多头研究员 ⟷ 空头研究员      ← 就同一份数据对撞
   ↓
【风控把关】风险管理官                      ← 独立审查，定仓位上限
   ↓
【交易执行官】合成最终方案                  ← 输出可执行指令
   ↓
【人类拍板】通过 / 修改 / 驳回              ← human-in-the-loop
```

### 8 位委员

| 角色 | 关注点 |
|---|---|
| 基本面分析师 | 估值（PE/PB）、市值规模、成长性；**板块模式下改看成分股结构** |
| 技术分析师 | 均线排列、MACD、RSI、布林带、量能 |
| 新闻分析师 | **金十数据真实快讯**，区分「直接相关」与「宏观要闻」 |
| 情绪分析师 | 资金流向、涨跌家数、涨停数、量比 |
| 多头研究员 | 找上行驱动，反驳空头 |
| 空头研究员 | 找下行风险，反驳多头 |
| 风险管理官 | 按波动率定仓位上限、设止损 |
| 交易执行官 | 综合全部意见，输出评级 + 价位 + 执行指令 |

### 有 key 和没 key 的区别

- **有 API key**：每个 Agent 由大模型驱动，输出自然语言判断
- **没 API key**：切换到内置规则引擎 —— 基于真实指标做判断，论点来自数据计算

两条路径产出的数据结构完全一致，所以界面、价位、共识度都不受影响。
界面上会标明当前用的是哪条（左下角）。

## 数据来源

**全部免费、无需申请 key。**

| 数据 | 主源 | 备源 |
|---|---|---|
| A股 / 美股行情 | **同花顺** | 东方财富 → 腾讯 |
| A股 / 美股日K | **同花顺** | 腾讯 → 东方财富 |
| A股板块列表 | **同花顺**（枚举指数代码空间） | — |
| A股板块指数K线 | **同花顺** | 腾讯 → 成分股合成 |
| A股成分股/涨跌家数/资金流 | 东方财富 | — |
| 美股板块 | **同花顺**（SPDR 行业 ETF 代理） | 腾讯 |
| 财经快讯 | **金十数据** | 金十备用接口 |

### 为什么换成了同花顺

**东方财富的限流是直接原因。** 它的 `push2`（行情/列表）很宽松，但 `push2his`（K线）极其严格 ——
连续请求二十几次之后，股票和板块的 K 线**一起被封半个多小时**。换镜像域名也解决不了：
扫过 14 个编号镜像，只有一个偶尔能用。

同花顺的 `d.10jqka.com.cn` 是另一个量级：**单次 40–150ms，几百次连续请求从未被拒，
不需要 cookie、不需要签名。** 所以 A 股与美股的行情和 K 线现在都走它，东财和腾讯只做降级备源。

### 同花顺接口的几条要点

**板块代码要靠枚举，它没有列表接口。** 行业指数在 `881xxx`（约 90 个），概念指数分两段：
老概念 `885xxx`（约 340 个）和新概念 `886xxx`（约 110 个）。做法是对编号空间做一次全扫
（约 1900 个请求、20 秒），把没有 K 线的剔除掉 —— 有一批像 `885284 稀缺资源` 这样已经停更的板块，
**有名字但没有行情**，留着只会让分析出错。扫完约 480 个存活板块，结果缓存 7 天。

**K 线按自然年返回，要拼接。** `last.js` 永远只给最近 140 根，不够算 MA60 和 60 日区间，
所以要取当年文件再加上一年的，合并去重后截取 250 根。板块指数同样适用。

**实时行情的字段是内部数字编号**，没有公开文档。映射是逐字段跟腾讯的同一只股票对出来的：
`6`=昨收、`7`=今开、`8`=最高、`9`=最低、`10`/`30`=现价、`13`=成交量、`19`=成交额、
`199112`=涨跌幅、`2034120`=市盈率、`592920`=市净率、`3475914`=总市值。

**它的成交量单位是「股」，不是「手」。** 东财和腾讯都用手，所以入库前统一除以 100。
不转换不影响量比（比值会约掉），但绝对量值会差 100 倍。

**成分股仍然是东财的。** 同花顺的成分股只有服务端渲染的 HTML 表格，概念板块一页 10 只、
行业一页 20 只，拿全一个板块要翻十几页；东财 `clist` 一次请求给 500 只，还自带市值、PE 和资金流向，
而且它在 `push2` 域，从来不是被限流的那一层。所以这一层保留东财 —— 480 个板块里有 347 个
（72.3%）能按名称匹配到东财同名板块；匹配不到的仍有完整指数 K 线，只是没有成分股明细。

**美股也能走同花顺，而且不需要交易所后缀。** 代码是 `usa_` 加 ticker（`usa_NVDA`），
行情字段与 A 股完全同一套（含中文名「英伟达」「苹果」、PE、PB、市值，以及 52 周高低），
K 线同样是按年拼接。腾讯那边必须写成 `usNVDA.OQ`，**不带后缀不报错，只是安静地返回 1 根 K 线** ——
同花顺没有这个陷阱，写错了直接 404。实测 18 个 ticker（大盘股、小盘股、中概股、行业 ETF）全部命中，
与腾讯重叠的 260 个交易日收盘偏差小于 0.1%。

**美股与 A 股的成交量口径不同，不能一并除以 100。** 同花顺给 A 股的成交量单位是「股」，
而东财和腾讯用「手」，所以要 ÷100 对齐；美股这边同花顺、腾讯、东财本来就都是「股」，
实测同一交易日 NVDA 的比值精确等于 1.0000，因此美股不做任何换算。

**金十快讯每页固定 21 条**，`count`/`limit`/`size` 参数全部无效，只能靠 `max_time` 串行翻页。
好处是**翻页完全不限流**，1000 条约 8.5 秒。

### 板块 K 线的兜底顺序

1. **同花顺板块指数** —— 每个存活板块都有真实指数，不受限流。这已经是常态路径，不是运气好才走得到。
2. **腾讯板块指数**（`pt` 代码）—— 给早期记录留的兼容路径。
3. **成分股合成指数** —— 最后兜底，取市值最大的 20 只成分股加权合成。

第三级有两个要点：

- **必须锚定**：合成序列从 1000 点起算，而真实板块指数是 8000+ 点。
  必须整体缩放让末值等于实时指数点位，否则支撑/压力位会差 5 倍、结论完全错乱。
- **必须标注**：合成序列的趋势可靠，但历史绝对点位与官方指数有偏差。
  界面和 Agent 的 prompt 都会声明"这是合成序列"，不会冒充官方指数。

改造前约一半板块要靠第三级，现在只有东财特有的板块（如 `BK1600 医疗研发外包`）才会落到这里。

## 已知限制

**数据层面**

- A股与美股的行情、K线都已不再经过东财的 `push2his`；这个会封 IP 的接口现在只在所有主备源都失败时才会被触及。
- 同花顺**不提供美股指数**（`IXIC` / `SPX` / `DJI` 全部 404），只覆盖个股与 ETF。本系统不分析美股指数，暂不受影响。
- 美股个股名称现在是同花顺给的中文名（「英伟达」「Lumentum控股」「阿里巴巴」），与之前东财/腾讯返回的英文名不同。
- 板块体系换成了同花顺，**东财的 `BKxxxx` 代码不再是主输入**。旧代码仍能解析（按名称映射到同花顺同名板块），但更推荐用 `88xxxx` 或直接输中文名。
- 成分股明细依赖东财：480 个板块里有 347 个（72.3%）能匹配到同名东财板块，其余板块指数 K 线完整，但没有成分股、涨跌家数与资金流向。
- 合成指数（第三级兜底）的**历史绝对点位与官方指数有偏差**，适合看趋势方向和当前支撑压力，不适合引用长期收益率。
- 板块列表的构建要全扫约 1900 个同花顺代码（约 20 秒），首次启动偏慢；之后走 7 天磁盘缓存。

**分析层面**

- 新闻匹配基于关键词（板块名 + 龙头股名）。冷门板块可能匹配不到直接相关快讯，此时会给宏观要闻。
- 规则引擎的分析深度明显不如大模型 —— 它能算、能对比，但不擅长讲因果。
- **真实大模型调用路径未经充分验证**（开发环境无 API key），首次配置 key 后请留意输出。
- 同一标的重复分析，结论可能有差异（数据是实时的）。

**风险提示**

- 本系统**不接入任何交易通道，不会真实下单**。底部的决策按钮只是记录你的判断。
- 所有输出**仅供研究学习，不构成投资建议**。
